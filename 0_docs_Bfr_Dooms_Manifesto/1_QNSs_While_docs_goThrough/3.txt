1. Why routes, What is controller, how to write code for it??
    ## 1️⃣ Why Routes?
    - **Definition:** Routes define the **endpoints** of your API — basically the paths (URLs) that clients can call.
    - **Purpose:**
    - Organize your API by functionality (`/users`, `/products`, `/orders`).
    - Map HTTP methods (`GET`, `POST`, `PUT`, `DELETE`) to specific actions.
    - Keep code modular and maintainable.
    - **Example:**
    ```javascript
    // routes/users.js
    const express = require('express');
    const router = express.Router();
    const userController = require('../controllers/userController');

    router.get('/', userController.getAllUsers);
    router.get('/:id', userController.getUserById);
    router.post('/', userController.createUser);
    router.put('/:id', userController.updateUser);
    router.delete('/:id', userController.deleteUser);

    module.exports = router;
    ```

    👉 Here, each route points to a **controller function** that handles the logic.

    ---

    ## 2️⃣ What is a Controller?
    - **Definition:** A controller is a **function or module** that contains the business logic for handling requests and sending responses.
    - **Purpose:**
    - Separates **routing** (URLs) from **logic** (what happens when that URL is called).
    - Makes code cleaner, reusable, and easier to test.
    - **Structure:**
    - Receive request (`req`)
    - Process data (query DB, validate input, apply logic)
    - Send response (`res`)

    ---

    ## ✍️ Example Controller Code

    ```javascript
    // controllers/userController.js

    let users = [
    { id: 1, name: "Rehaan", email: "rehaan@example.com" },
    { id: 2, name: "Aisha", email: "aisha@example.com" }
    ];

    // Get all users
    exports.getAllUsers = (req, res) => {
    res.json(users);
    };

    // Get user by ID
    exports.getUserById = (req, res) => {
    const user = users.find(u => u.id == req.params.id);
    user ? res.json(user) : res.status(404).send("User not found");
    };

    // Create new user
    exports.createUser = (req, res) => {
    const newUser = { id: users.length + 1, ...req.body };
    users.push(newUser);
    res.status(201).json(newUser);
    };

    // Update user
    exports.updateUser = (req, res) => {
    const index = users.findIndex(u => u.id == req.params.id);
    if (index !== -1) {
        users[index] = { id: parseInt(req.params.id), ...req.body };
        res.json(users[index]);
    } else {
        res.status(404).send("User not found");
    }
    };

    // Delete user
    exports.deleteUser = (req, res) => {
    users = users.filter(u => u.id != req.params.id);
    res.status(204).send();
    };
    ```

    ---

    ## 🔗 How Routes and Controllers Work Together
    - **Routes** define *where* requests go (`/users`, `/users/:id`).
    - **Controllers** define *what happens* when those requests are made (fetch, create, update, delete).

    This separation is part of the **MVC pattern (Model–View–Controller)**:
    - **Model** → Data layer (database).
    - **View** → UI layer (frontend).
    - **Controller** → Logic layer (API handling).

    ---

    ✅ In short:  
    - **Routes** = API endpoints.  
    - **Controllers** = Functions that handle the logic behind those endpoints.

    ## 📂 Why Have a `routes/` Folder?
    - **Organization:** Keeps all route definitions in one place instead of cluttering `app.js`.
    - **Scalability:** Easier to manage when your app grows (e.g., `users`, `products`, `orders`).
    - **Separation of concerns:** Routes only define *paths* and *methods*, while controllers handle the *logic*.

    ---

    ## 🏗️ Typical Project Structure

    ```
    project/
    │
    ├── app.js              # Entry point
    ├── routes/             # Folder for route definitions
    │   ├── users.js        # User-related routes
    │   ├── products.js     # Product-related routes
    │   └── index.js        # Combine all routes
    ├── controllers/        # Folder for controllers (logic)
    │   ├── userController.js
    │   └── productController.js
    └── models/             # Database models (optional)
    ```

    ---

    ## 📌 Example: `routes/users.js`

    ```javascript
    const express = require('express');
    const router = express.Router();
    const userController = require('../controllers/userController');

    // Define routes and map them to controller functions
    router.get('/', userController.getAllUsers);
    router.get('/:id', userController.getUserById);
    router.post('/', userController.createUser);
    router.put('/:id', userController.updateUser);
    router.delete('/:id', userController.deleteUser);

    module.exports = router;
    ```

    ## 📌 Example: `routes/index.js`

    ```javascript
    const express = require('express');
    const router = express.Router();

    // Import route modules
    const userRoutes = require('./users');
    const productRoutes = require('./products');

    // Use them under specific paths
    router.use('/users', userRoutes);
    router.use('/products', productRoutes);

    module.exports = router;
    ```

    ---

    ## 📌 Example: `app.js`

    ```javascript
    const express = require('express');
    const app = express();
    const routes = require('./routes');

    app.use(express.json());

    // Use the combined routes
    app.use('/api', routes);

    app.listen(3000, () => {
    console.log("Server running on http://localhost:3000");
    });
    ```

    ---

    ✅ **Summary:**  
    - **Routes folder** = defines endpoints.  
    - **Controllers folder** = contains logic.  
    - **app.js** = entry point that wires everything together.  

    This way, your project stays clean and modular.
